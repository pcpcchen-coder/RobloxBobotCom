# 測試計畫｜RoboPush Arena MVP

狀態：**測試尚未執行；全部 Not Run**。自動化測試與 Roblox Studio/真機人工測試應分別回報。

## 測試環境

- Roblox Studio Server & Clients：至少一台 Server 和兩位 Client；每個 Client 對應一個不同 Player。
- 桌機：鍵盤滑鼠；行動：手機真機；手把：有實際硬體時測。
- 覆蓋正常延遲與可重現的高延遲狀況（若 Studio 測試網路條件可用）。
- 記錄 build commit、日期、裝置、測試者、場景、步驟、預期/實際結果、證據 URL。

## 檢查細節

### 命中與擊退

- 從正面、側面、背面、高低差、重疊角色測 Dash 命中窗口。
- 多個服務端 frame 命中同一人只能套用一次衝量。
- 角色被重擊時驗證 0.4 秒抗擊退窗口（若採用）。
- Network Ownership 影響記錄成待調查事項，不可僅靠兩畫面「看起來差不多」宣稱完全公正。

### 比賽狀態

- WAITING 無法得分；COUNTDOWN 不接受移動/技能。
- RUNNING 到 RESULT 過程只結算一次。
- COUNTDOWN、重生中、RESULT 狀態都不得偷施放特殊技能。
- 以伺服器 timestamp 判斷 CD、比賽結束與縮圈時間。

### 視覺化驗證報告

每次實測至少留以下證據（形式可用 Markdown 表與截圖/影片）：

- **需求 → 測試案例 → 結果 → 證據** 的矩陣。
- 最近一次事件時間線（技能起始、命中、掉落、計分、結算）。
- 修復前/後對照與重現步驟。
- 失敗、Blocked 和未覆蓋項目；不可讓 Dashboard 把 Not Run 當通過。

## 完成定義

1. 功能/安全關鍵案例 T01–T22 均有**真實記錄**，未執行標 Not Run、環境不可測標 Blocked。
2. 測試過程不存在重大 Crash、無法開局、雙重計分、分數作弊。
3. 連續 30 場不出現阻礙遊玩的重大問題。
4. PC + 至少一支手機真機完成完整對戰驗證；手把若沒有硬體可 Blocked 並列發佈限制。
5. 每個修正關聯 commit/PR 與案例 ID。
